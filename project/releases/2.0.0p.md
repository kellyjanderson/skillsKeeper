# SkillsKeeper 2.0.0p Planning Release

Status: Planning

## Intent

`2.0.0p` is a GitHub-only planning release for the next major SkillsKeeper
architecture. It is not a Python package version and must not update
`pyproject.toml`.

This release collects architecture, ACDs, and follow-on specification sources
for the skill library, graph-indexed checkout, proposal-review, fully managed
local skills, and global archive mirror-removal work.

## Planned User Outcomes

- Reusable skills can be managed as a local library instead of only as global
  Codex mirrors or per-project folders.
- Projects can check out one skill, an index, or a profession/context tree into
  `.agents/skills`.
- `.agents/skills` becomes an intentional active selection surface with clear
  ownership rules.
- Library skill updates require proposal review before reusable source changes.
- Global archive removes generated Codex mirrors for archived global skills.
- Local project skills keep backup-only behavior by default, with an opt-in
  fully managed mode for stricter projects.

## Exclusions

- No Python package artifact is implied by this planning release.
- No Kuzu dependency is committed until implementation specs validate the
  dependency boundary.
- No Codex hook is required for the first library update proposal flow.
- Linux, Windows, and non-Codex agent integrations are welcome future
  directions, but this planning release defines the current Codex and macOS
  service baseline first.
